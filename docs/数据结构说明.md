# 数据结构说明（db/ 分层与清洗配方）

> 本文档定义 `db/` 的目录规范。**改数据库结构前请先读这里。**
> 所有路径必须通过 `database/config.py` 获取，禁止在业务代码里手写 `"db/xxx"` 字符串。

---

## 1. 三层结构

```
db/
├── _MANIFEST.json          全库说明：层级 / 规则 / 只读约定
│
├── frozen/                 ① 原始层 —— 只读，数据源原样
├── cleaned/                ② 加工层 —— 按清洗配方分目录，可从 frozen 重建
└── _legacy/                ③ 历史归档 —— 旧管线产物，不再更新，可删
```

| 层 | 内容 | 可写方 | 可重建 |
|---|---|---|---|
| `frozen/` | 数据源原样落盘（tushare 等），未做任何清洗/换算 | **仅下载器** | ❌ 丢了要重新下载 |
| `cleaned/` | 清洗/派生结果，一个配方一个目录 | 清洗脚本 | ✅ 从 frozen 重建 |
| `_legacy/` | frozen 层建立之前的旧产物，口径与现在不一致 | 无（冻结） | ❌ 不重建，可删 |

**一句话记忆**：`frozen` 是"事实"，`cleaned` 是"观点"，`_legacy` 是"旧观点"。

---

## 2. 为什么按「清洗配方」分子目录

同一份原始数据，用不同方式加工，结果**口径完全不同**：

| 原始数据 | 加工方式 A | 加工方式 B |
|---|---|---|
| `frozen/valuation`（市值=**万元**，列名 `turnover_rate`） | 原样使用 | **亿元**归一 + 改名为 `turnover` |
| `frozen/daily_raw`（不复权） | 直接用不复权价 | 乘复权因子得**前复权价** |
| `frozen/daily_raw` | 只丢幽灵K线 | 再剔除 ST / 停牌 / 上市未满 N 日 |
| `frozen/daily_raw` | — | 派生**涨跌停价** |

这些口径如果混在同一个目录里，读取方**无法判断拿到的是哪一种**。

本项目就真的踩过这个坑：历史上 `db/daily` 同时被写入过前复权价和不复权价
（因为已废弃的 `DailyDownloader` 和 `rebuild_cleaned.py` 都往它写），
导致 `load_daily(adjust='qfq')` 变成**双重复权**，价格被错误地乘了两次因子。

因此规定：**一种清洗方式独占一个目录，目录名 = 配方名。**

---

## 3. 清洗配方注册表

配方登记在 `database/config.py` 的 `RECIPES`，同时导出到 `db/cleaned/_RECIPES.json`。

| 配方名（=目录名） | 产出 | 来源 | 规则 | 产出脚本 |
|---|---|---|---|---|
| `daily_basic` | 清洗后日线 | `frozen/daily_raw` | 丢幽灵K线(vol=0/NaN)、价格≤0、OHLC违规、VWAP三角越界(0.95~1.05) | `scripts/rebuild_cleaned.py`、`scripts/daily_update.py` |
| `limit_price` | 涨跌停价 | `cleaned/daily_basic` | 主板±10% / 创业板·科创板±20% / 北交所±30% / ST±5% | `database/downloader/meta.py`、`scripts/daily_update.py` |
| `daily_akshare_legacy` | 【废弃】akshare 日线 | 网络 | 双源交叉校验 | `database/downloader/daily.py`（已废弃） |

数据布局：

```
db/cleaned/daily_basic/year=2024/000001.parquet
db/cleaned/limit_price/year=2024/000001.parquet
db/frozen/daily_raw/year=2024/000001.parquet
db/frozen/valuation/year=2024/000001.parquet
```

分区约定：**按年 + 代码** `year=YYYY/<code>.parquet`。
非年度数据（股票列表、行业映射、期权合约等）用 `year=2005/<name>.parquet`
（`2005` 是"元数据分区"占位，沿用历史约定）。

## 4. 只读约定是「代码强制」的，不只是嘴上说说

`database/storage.py` 会在写入前检查目标目录：

```python
Storage("daily_raw").save(df)                    # ✗ 抛 FrozenWriteError
Storage("daily_raw", allow_frozen=True).save(df) # ✓ 只允许下载器这样写
Storage("daily").save(df)                        # ✓ 写入 cleaned/daily_basic
```

被拒绝时抛 `FrozenWriteError` 并给出正确写法提示：

```
D:\quant\db\frozen\daily_raw 属于只读的 frozen 层。
  下载器请用 Storage('daily_raw', allow_frozen=True)
  清洗产物请写入 cleaned/ 下的配方目录（见 database.config.RECIPES）
```

这样做的好处：**清洗/分析代码不可能"手滑"污染可信源**。
下载器是唯一被允许写 frozen 的角色，它们在 `database/downloader/base.py` 里
统一传 `allow_frozen=True`。

## 5. 路径 API（业务代码只用这四个）

```python
from database.config import dir_of, recipe_dir, parquet_glob, is_frozen

dir_of("daily")          # -> db/cleaned/daily_basic   （清洗产出，走配方路由）
dir_of("daily_raw")      # -> db/frozen/daily_raw      （frozen 数据集）
dir_of("valuation")      # -> db/frozen/valuation
recipe_dir("limit_price")# -> db/cleaned/limit_price   （按配方名取）
parquet_glob(dir_of("daily"))
                         # -> 'D:/quant/db/cleaned/daily_basic/year=*/*.parquet'
is_frozen(path)          # -> True/False
```

**不要**写：

```python
pd.read_parquet("db/daily/year=2024/000001.parquet")      # ✗ 硬编码，改结构就炸
con.execute("... FROM read_parquet('db/daily/year=*/*.parquet')")  # ✗ 同上
```

**要**写：

```python
g = parquet_glob(dir_of("daily"))
con.execute(f"... FROM read_parquet('{g}')")               # ✓
```

> 历史教训：本项目原来在 7 个文件里硬编码 `db/daily/...` 和 8 个文件里
> 各自用 `Path("db")` 相对路径，导致换目录结构要改十来个地方，
> 且从不同 cwd 运行会分裂成两棵数据库树。现在只改 `config.py` 一处。

## 6. 怎么新增一种清洗方式

以"新增前复权日线物化"为例：

**第 1 步** 在 `database/config.py` 的 `RECIPES` 里登记：

```python
RECIPES = {
    ...
    "daily_qfq": {
        "dataset": "daily_qfq",
        "desc": "前复权日线（物化，避免每次现场计算）",
        "source": "cleaned/daily_basic + frozen/adjust",
        "rules": "close_qfq = close × adj_factor / adj_factor_latest",
        "producer": "scripts/build_qfq.py",
    },
}
```

**第 2 步** 写产出脚本，路径从 config 取：

```python
from database.config import dir_of, FROZEN_ROOT
from database.storage import Storage

dst = Storage("daily_qfq")          # 自动落到 db/cleaned/daily_qfq/
src = dir_of("daily")               # db/cleaned/daily_basic
...
dst.save(df, year=2024, code="000001", force=True)
```

**第 3 步** 验证：

```powershell
python -c "from database.config import dir_of; print(dir_of('daily_qfq'))"
```

**第 4 步** 在本文档第 3 节的表格里加一行。

不需要改任何其它代码——`dir_of()` / `recipe_dir()` 会自动路由。

## 7. `_legacy/` 是什么，能不能删

`_legacy/` 里是 **frozen 层建立之前** 的旧管线产物，口径与现在的 frozen 不一致：

| 目录 | 与 frozen 的差异 | 能否删 |
|---|---|---|
| `valuation_norm` | 市值已由**万元换算成亿元**，`turnover_rate`→`turnover`，只有 7 列 | 能（frozen 有原始数据） |
| `st_flagged` | 在 `frozen/st` 基础上多一列派生 `is_st` | 能（可重新派生） |
| `etf_akshare` | akshare 源、**中文列名**，与 `frozen/etf`（tushare fund_basic）内容不同 | 能（如需可重新下载） |

**没有脚本会更新它们。** 确认不再需要后可整体删除释放空间：

```powershell
Remove-Item D:\quant\db\_legacy -Recurse -Force
```

> ⚠️ 删除前请确认你不需要"亿元归一"的历史估值。需要的话，正确做法是从
> `frozen/valuation` 重新派生到 `db/cleaned/valuation_norm/` 并登记配方。

## 8. 日常操作

```powershell
# 看结构
python -c "from database.config import DB_ROOT, dir_of, RECIPES; [print(k,'->',dir_of(k)) for k in ['daily','limit','daily_raw','valuation']]; print(RECIPES.keys())"

# 校验数据质量（读新路径）
python scripts/validate_data.py --check unique
python scripts/validate_data.py --check schema

# 全量重建清洗层（先删后建，从 frozen 派生）
python scripts/rebuild_cleaned.py --verify

# 每日增量更新（下载到今天 + 重建当年清洗层与涨跌停）
python scripts/daily_update.py

# 回测（自动走 cleaned/daily_basic）
python scripts/backtest.py --symbol 000001 --start 2024-01-01 --end 2024-12-31 --strategy MA
```

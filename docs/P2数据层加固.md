## 一、修了三个会导致数据损坏或永久缺失的问题

### 问题 1：写入不是原子的 → 崩溃即永久损坏

`Storage.save()` 原来直接 `df.to_parquet(最终路径)`。若进程在写一半时被杀
（磁盘满 / 断电 / Ctrl-C），会留下**无法读取的 parquet**。

更糟的是：`save()` 有"文件已存在就跳过"的断点续跑语义（`if path.exists() and not force: return`），
所以这个损坏文件**之后永远不会被重写**，形成永久损坏，而且只在读取时才暴露。

**修复**：先写 `.tmp`，再 `os.replace()` 原子替换。

```python
tmp = path.with_name(f"{path.name}.tmp{os.getpid()}")
try:
    df.to_parquet(tmp, index=False)
    os.replace(tmp, path)          # 原子：要么全有，要么全无
finally:
    if tmp.exists():
        tmp.unlink(missing_ok=True)
```

实测：模拟"写一半失败"后，正式文件不存在、临时文件也不残留。

### 问题 2：断点文件无容错 → 一次断电之后每次运行都报错

```python
def load_checkpoint(self):
    if self.checkpoint_file.exists():
        return json.loads(self.checkpoint_file.read_text(...))   # ← 没有 try
```

断电可能把 `_checkpoint.json` 写成半截，之后**每次运行都抛 JSONDecodeError**，
整个下载流程再也起不来。

**修复**：损坏时备份为 `.json.corrupt` 并重建为空断点；同时加内存缓存，
避免 `mark_done` 每次都重读整个 JSON（5000 只股票 = O(n²) 次读盘）。

> 说明：`.corrupt` 备份是刻意保留的——断点丢失意味着几千只股票会被重下，
> 应当能被人发现，而不是静默重来。

### 问题 3：下载失败被当成"这只股票没数据" → 永久缺股

`TushareClient.call` 的限频分支是：

```python
if "最多" in msg or "每分钟" in msg or "频率" in msg:
    time.sleep(5)
    continue                 # ← 重试次数耗尽后 for 循环自然结束
# 循环结束 → 隐式 return None
```

而调用方普遍写成：

```python
df = self._tc.adj_factor(...)
if df is None or df.empty:
    self.storage.mark_done(code)     # ← None 被当成"没有数据"
```

**后果**：一次网络抖动 → 重试耗尽 → 返回 `None` → 该股票被永久标记完成，
`resume=True` 再也不会重下，**数据静默缺失**。

**修复**：重试真正耗尽时抛 `TushareCallError`。现在语义清晰：

| 情况 | 行为 | 是否写断点 |
|---|---|---|
| 接口失败（网络/限频/权限） | 抛 `TushareCallError` | ❌ 不写，下次重试 |
| 接口正常返回空 | 返回空 DataFrame | ✅ 写（确实没有数据） |

另外旧实现只在进循环前 `wait()` 一次，**重试是绕过限流的**——现在每次尝试都限流。

### 附带：磁盘保护不会被静默吞掉

下载器里到处是 `except Exception` 兜底，而 `DiskFullError` 继承 `Exception`
→ 磁盘满了会被吞掉，继续跑。

改为继承 **`BaseException`**（与 `KeyboardInterrupt` / `SystemExit` 同类），
一定向上传播。测试里直接验证："`except Exception` 捕获不到它"。

## 四、顺带发现的环境坑（与代码无关，但会咬人）

写测试时踩到两次权限问题，都值得记下来：

1. **`tempfile.mkdtemp()` 建的目录里无法建子目录** —— 它以 `0o700` 创建，
   其 ACL **不含本环境的沙箱身份**，于是"能在里面建文件、却建不了子目录"。
   改用普通 `mkdir()`（继承父目录 ACL）。
2. **从旧目录 rename 过来的文件可能保留旧 ACL** —— 之前 `db/limit → db/cleaned/limit_price`
   迁移后，6.6 万个文件保留了不含沙箱身份的 ACL，导致删除/重建被拒，
   `icacls` 也改不动（它同样以沙箱身份运行）。最后靠提权才清理掉。

> 实践建议：**迁移或解压进来的大批文件，先确认权限再让脚本去动它。**

## 五、仍未处理

1. **`mark_done` 的粒度仍是"股票"而非"股票 × 年份 × 区间"**：
   某只股票部分年份写入成功、部分失败时，仍会被整体标记完成。
2. **断点写入仍是每次全量重写 JSON**（缓存只解决了读放大，没解决写放大）。
   5000 只股票 = 5000 次全量写。可以改成追加式日志或定期 flush。
3. **下载器对 `TushareCallError` 的处理仍是"记日志后跳过"**，
   没有失败清单 / 重试队列 / 非零退出码，跑完无法知道哪些股票失败了。

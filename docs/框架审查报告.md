## 2. 对现有架构的修改意见

### 2.1 【第一优先】建立唯一账本，消灭"双份记账"

现状：`BacktestEngine` 维护 `self.portfolio`，而 `scripts/backtest.py:164-203` 的 `build_equity_curve()` **用成交记录重新推一遍现金和持仓**，两套账本从不互相校验（实测差 0.96%）。而 `engine.py:108` 其实已经把每笔后的 `portfolio.total_value` 记进了 `trades["balance"]`，却没人用。

**改法**：
1. `build_equity_curve()` 删除，改为**每个 bar 结束后由引擎快照账户**：`equity[i] = portfolio.total_value`，并把逐 bar 权益直接存进引擎（`self.equity_curve`），`Metrics.compute` 只接受引擎产出的那一条曲线。**单一数据源。**
2. 成交记录里增加独立字段：`fill_price`（真实成交价）、`commission`、`stamp_duty`、`transfer_fee`、`slippage_cost`，不再把费用混进 `filled_amount`。`Order.filled_amount` 语义回归"成交额"。
3. 加一条**自检断言**（可放在 `Metrics.compute` 前）：`abs(equity[-1] - portfolio.total_value) < 1e-6`，以及"每笔交易的现金变动 = 成交额 ± 费用"。这类不变量一旦跑起来，本次报告里大半的账目 bug 都会立刻暴露。

### 2.2 信号模型：`Action` 三态 → 目标仓位 / 订单意图

现状 `Signal(action, size, price, reason)` 表达不了"目标仓位 30%""从 3 只换到 5 只""平空"。`TurtleStrategy` 的做空入场发 `SELL`（`strategy/classic.py:55,79,89`），而引擎把 `SELL` 当"平多"且要求 `position>0` → **空头信号静默失效，策略内部 `_position` 却已改成 -1**，之后所有止损判断全错。

**改法**（建议目标仓位制，最省心）：
```python
@dataclass
class Target:
    symbol: str
    weight: float          # 目标权重，0 = 清仓；负数=允许做空（若账户支持）
    reason: str = ""
# Strategy.on_bar(...) -> list[Target]（多标的）或 Target（单标的）
```
引擎负责"当前权重 → 目标权重"的差额下单，好处：策略不再关心资金/股数/手续费，天然支持轮动与调仓，且与 `semiconductor_rotation.py` 的等权逻辑直接对应。若必须保留事件式信号，至少要把 `Action` 拆成 `OPEN_LONG/CLOSE_LONG/OPEN_SHORT/CLOSE_SHORT`。

### 2.3 策略无状态化（消除状态脱钩）

禁止策略持有 `_in_position`/`_prev_signal` 之类持仓状态；策略只根据**传入的只读上下文**（历史窗口 + 当前持仓）计算目标。持仓的唯一真相在 `Portfolio`。改造方式：`on_bar(ctx, i)`，`ctx` 提供 `ctx.position(symbol)`、`ctx.cash`、`ctx.history(n)`。这样策略才能被安全地并行用于参数优化，也能被单元测试（喂固定数据 + 固定持仓，断言输出目标）。

### 2.4 事件驱动 + 显式时序契约（根治未来函数）

现在"第 i 根 bar 决策 + 第 i 根 bar 收盘成交"是隐式的，且策略能拿到整张 `data` 表（`strategy/base.py:27` 传整个 DataFrame）——**策略里任何 `data['close'].max()` 全样本统计都是未来函数**（`data/preprocessor.py:179-184` 的 `drop_outliers` 就是这种写法）。

**改法**：
1. `on_bar` 只给到 `i` 为止的**切片视图**（或 `ctx`），物理上禁止访问未来行。
2. 成交时点显式配置：`exec_price ∈ {next_open, next_close, close}`，默认 `next_open`（A股最贴近现实），并在回测报告里打印所采用的约定。
3. 把 `backtest/lookahead.py` 真正接进流程：`scripts/backtest.py:216` 那两个 import 必须**被调用**，且 `assert_no_lookahead` 对"决策日 ≥ 数据可获得日"做硬断言；财务数据一律走 `ann_date`。
4. 加"延迟敏感性测试"作为标准工序：因子整体延后 1/3/5 天重跑，收益骤降即说明泄漏。

### 2.5 撮合层注入 A 股微观结构约束

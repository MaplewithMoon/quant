## 一、实现了什么

| 约束 | 旧行为 | 现行为 |
|---|---|---|
| **T+1** | 当日买当日可卖 | `Position.available` 记录可卖数量，引擎每根 bar 调 `new_day()` 解锁；当日买入当日不可卖 |
| **涨跌停** | 完全不管，涨停价照样买、跌停价照样卖 | 封板日拦截：参考价已在涨停 / 全天最低价未跌破涨停 → 不可买；跌停对称 |
| **停牌** | 停牌日照常成交 | `suspended` 标记为真时不成交 |
| **一手 100 股** | 可买任意股数（实测 20/21 笔不是整手） | `max_affordable_size()` 按 `lot_size` 向下取整，实测全部为 100 的整数倍 |
| **印花税 / 过户费** | 只有佣金，且因符号 bug 净额为 0 | `Order` 拆分 `commission` / `stamp_duty` / `transfer_fee`；印花税仅卖出单边 0.05%，过户费双边 0.001% |
| **成交时点** | 第 i 根 bar 收盘决策 + 同 bar 收盘成交（含未来函数） | `next_open`（默认）：第 i 根 bar 决策 → 第 i+1 根 bar **开盘**成交 |
| **策略可见数据** | 策略拿到整张 DataFrame，可读未来行 | 截断到当前 bar（`data.iloc[:i+1]`），物理上无法访问未来 |

被拦下的委托会记入 `engine.rejections` 并可按原因汇总，回测结束打印：

```
[制度约束] 被拦下的委托:
       7 次  参考价已在涨停
       1 次  参考价已在跌停
       1 次  停牌不可买
```

## 二、数据实例对照

同一份数据库 / 同一策略 / 同一区间（`000001`，2024 全年，MA，初始 100 万）

### 1) 成交时点：这是影响最大的一项

| 组合 | 成交时点 | 总收益率 | 最大回撤 | 总费用 |
|---|---|---:|---:|---:|
| A 旧行为 | same_close | **3.27%** | -16.10% | 7,945 |
| C next_open | next_open | **1.89%** | -16.88% | 7,954 |

**改变成交时点让收益降低 1.38pp** —— 证明"同 bar 收盘决策并按同一收盘价成交"确实在虚增收益（决策用到了当天收盘信息，却按同一个价格成交）。

成交日期整体后移一天，印证了撮合时点：

```
【A 旧行为】2024-01-30  buy  价 7.9800  125,200 股
【D 新默认】2024-01-31  buy  价 7.9500  125,700 股   ← 次日开盘成交
```

### 2) 费用：印花税是隐藏的大头

单笔卖出明细（新默认口径）：

```
2024-03-18  sell  价 8.8600  125,700 股  费用 679.36
           (佣金 111.37 / 印花税 556.85 / 过户费 11.14)
```

- 印花税 **556.85** vs 佣金 **111.37** —— 印花税是佣金的 5 倍
- 60 只样本股扫描合计：佣金 370,685 / **印花税 914,302** / 合计 1,322,055
- **印花税占总费用 69%**，而旧模型里这部分**完全没算**

### 3) 制度约束在真实数据上确实会命中

60 只随机样本股 × 2 个策略（3,728 笔成交）：

| 拦截原因 | 次数 |
|---|---:|
| 参考价已在涨停，买不到 | 7 |
| 参考价已在跌停，卖不掉 | 1 |
| 停牌不可买 | 1 |

逐条核对均为真实封板/停牌，例如：

```
002644 DualThrust  参考价已在涨停(8.26≥8.26)，买不到
688287 DualThrust  停牌不可买
600110 DualThrust  参考价已在跌停(2.72≤2.72)，卖不掉
```

## 三、过程中发现并修复的数据缺陷

实现涨跌停约束时发现 **`cleaned/limit_price` 这份数据本身是坏的**，必须一并修掉，否则规则会乱拦。

### 问题 1：涨跌停价是从**前复权价**派生的

核查 `000719`：

| 日期 | limit 表的 pre_close | 真实昨收 | 说明 |
|---|---:|---:|---|
| 2024-01-02 | 8.39 | 9.76 | 差 14% |

`limit_up` 自身是自洽的（100% 等于 `pre_close×1.1`），但它的 `pre_close` 并不是真实昨收 —— 说明这份数据是在 `db/daily` 还混着前复权价时（`DailyDownloader` 污染期）派生出来的遗留产物，而上次重建清洗层**没有重建它**。

后果：回测用前复权价，却拿不复权涨停价去比，有分红送转的股票会被误判。

### 问题 2：昨收口径错误

旧实现用 `close.shift(1)` 算昨收，导致：
- **每年首个交易日没有涨跌停价**（年内分区 shift 后 dropna）
- **除权除息日涨跌停价错误** —— 交易所用的是**除权后参考价**，不是上一日收盘价

实测 `000719` 2024-06-26（除权日）：官方 `pre_close` 9.76，而 `close.shift(1)` 给出 10.18 —— 相差 0.42 元的分红。

### 问题 3：板块/ST 规则有两套互相冲突的实现

- `database/downloader/meta.py`：有 ST 5%，**无**北交所规则
- `scripts/daily_update.py`：有北交所 920 的 30%，**无** ST 规则

两者写同一个目录、互相覆盖。

### 修复：新增 `scripts/rebuild_limit.py` 全量重建

- 改用 tushare **官方 `pre_close`**（已按除权调整）→ 同时解决年初缺失与除权日错价
- 板块/ST 规则集中到一处：科创板/创业板 ±20%、北交所 ±30%、主板 ST ±5%、主板 ±10%
- 结果：**72,971 文件 / 15,967,832 行**，与清洗层行数完全一致（不再有年初缺失）

### 判断逻辑同时改为「封板」口径

即使涨跌停价有几分钱误差也不易误判：

- **不可买** = 参考价已在涨停价上，**或**全天最低价都没跌破涨停价
- **不可卖** = 参考价已在跌停价上，**或**全天最高价都没涨破跌停价

若股票盘中曾跌破涨停价，说明确实买得到，就不拦。

**修复前后对比**（60 只样本股）：

| | 拒绝次数 | 典型记录 |
|---|---:|---|
| 修复前（混比 + 坏数据） | 8（近乎随机） | 漏掉绝大多数真实封板 |
| 按复权空间对齐后（仍是坏数据） | 145（**大量假阳性**） | `参考价 10.29 ≥ 涨停 8.86` ← 开盘高出涨停 16%，不可能 |
| 重建数据 + 封板口径后 | **9（全部合理）** | `参考价已在涨停(8.26≥8.26)`、`停牌不可买` |

## 五、怎么用

```powershell
cd D:\quant

# 新默认：次日开盘成交 + 制度约束 + 数据截断
python scripts/backtest.py --symbol 000001 --start 2024-01-01 --end 2024-12-31 --strategy MA

# 回到旧口径做对照
python scripts/backtest.py --symbol 000001 --strategy MA --fill-timing same_close --no-rules

# 单独调整费用
python scripts/backtest.py --symbol 000001 --strategy MA --stamp-duty 0.001

# 重建涨跌停价（改了板块规则或清洗层后）
python scripts/rebuild_limit.py --verify
```

编程式：

```python
from execution.market_rules import MarketRules
from backtest.engine import BacktestEngine, FILL_NEXT_OPEN

engine = BacktestEngine(initial_capital=1_000_000,
                        fill_timing=FILL_NEXT_OPEN,
                        market_rules=MarketRules(),      # 传 enabled=False 关闭
                        truncate_data=True)
trades = engine.run(ds, strategy)
print(engine.rejections.summary())   # {'参考价已在涨停，买不到': 7, ...}
```

## 六、已知局限（未处理）

1. **北交所/新三板（`920xxx`、`8xxxxx`）的 `pre_close` 在 tushare 里是垃圾值**（常见 0.01），
   导致这些代码的涨跌停价无意义。影响面约 0.067% 的行，且这些标的基本不在回测池内。
2. **新股上市首日/前 5 日**不设涨跌幅（注册制），当前一律按板块幅度计算。
3. **创业板 2020-08-24 之前是 ±10%**，当前一律按 20% 计算（会让涨停价偏高 → 少拦，属保守方向）。
4. **ST 判定依赖 `frozen/st` 的名称变更区间**，若区间数据缺失会退回 ±10%。
5. **无部分成交 / 涨跌停排队模型**：封板直接判为"完全不可成交"，
   现实中排板可能成交（保守方向，但会让回测偏悲观）。
6. **无流动性/冲击成本模型**：`semiconductor_rotation.py` 里的平方根冲击模型尚未上收进框架。

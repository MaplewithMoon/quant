# 日线局限与向小时/分钟级扩展的痛点记录

> **本文档的定位**：项目目标是**基于日线数据**的交易研究平台。
> 日线有物理上的局限，误差是必然的 —— 但只要**充分注明误差来源、评估误差量级**，
> 使其落在合理范围内就可以接受。
>
> **面向分钟/小时级的扩展不在当前目标内。** 本文档只做一件事：
> 把在日线实现里**撞到的、本质上是"因为只有日线才存在"的痛点**记下来，
> 供未来真要扩展时参考。**不在这里设计方案，也不为此改动现有架构。**

记录格式：**痛点 → 日线下能做到什么（已做） → 天花板在哪 → 扩展需要什么**。

---

## 已识别的痛点

### P1 · 涨跌停封板能不能成交（对应 T1·C5）

| | |
|---|---|
| **痛点** | 封板时"完全不可成交"是假设，不是事实。真实世界里排队可能成交一部分 |
| **日线天花板** | 日线只有 OHLC + 成交量 + 涨跌停价，**没有封单量、没有排队位置、没有撤单行为**。无法判断"队列前面有多少量"。 |
| **日线下已做 / 可做** | ① 先**埋点度量**：汇总被拦委托的量级（`result_report.render_rejections`）。占比 <1% 时声明即可<br>② 区分**一字板**（`open==high==low==close==板价`，全天无打开 → 维持不可成交，这是对的）与**非一字封板**（盘中打开过、有真实成交量 → 可引入 `fill_ratio` 参数，`可成交量 = min(委托量, 当日成交量 × fill_ratio)`）<br>③ 用 0 / 0.25 / 0.5 三档出绩效区间，**主结果取 `fill_ratio=0`（下界）** |
| **天花板** | 非一字封板的 `fill_ratio` 是**拍的参数**，不是从数据估出来的。它只能给"区间"，给不出"点估计"。 |
| **扩展需要** | 分钟/tick 级的**逐笔委托与成交**（或至少分钟级盘口），才能建真实排队模型。数据源线索：BaoStock、miniQMT。届时 `MarketRules` 的"不可成交"判定要换成"按队列位置部分成交"。 |
| **现在要不要做** | **不要**。先看埋点结果：被拦金额占比小就只是一句声明。 |

### P2 · 成交时点只有日线近似（对应 T1·C7 / F1）

| | |
|---|---|
| **痛点** | 日线只有四个价格点。策略"当日收盘决策"就只能用收盘价成交，这是**上界**；实盘做不到 |
| **日线天花板** | 无法表达"上午 10:30 出信号、10:31 成交"这类分钟级时序 |
| **日线下已做 / 可做** | ① 统一成 `next_open`（T日收盘决策 → T+1开盘成交）= **可实现口径，主结果**<br>② `same_close` 仅作对照，报告里**写死**声明为上界<br>③ 报告默认并排输出两版 + 差值（T1·② 待做） |
| **天花板** | 与聚宽的差异（F1）不可能完全消除 —— 聚宽是分钟撮合，我们是日线近似。只能**量出差多少**，不能**消除**。 |
| **扩展需要** | 分钟级价格序列 + 分钟级撮合。此时 `fill_timing` 要扩展成"信号时刻 → 下一分钟开盘/收盘"的映射。 |
| **现在要不要做** | 不需要分钟数据。**先把两版对照做成默认输出**，就能回答"结论对时点多敏感"。 |

### P3 · 停牌/复牌的日内细节（对应 B11）

| | |
|---|---|
| **痛点** | 日内临时停牌（`suspend_timing`，实测全区间 2,603 条）当天**仍有可交易时段**，但日线下只能按"这一天能不能交易"做二元判断 |
| **日线天花板** | 无法表达"09:38–09:49 停牌，其余时段正常"。日线的开/高/低/收是混了停牌与正常交易时段的**合成价格** |
| **日线下已做** | ① 全天停牌（无 K 线）与日内停牌（有 K 线）**分开处理**，日内停牌不整天禁掉<br>② 三层交叉验证（行情缺失 / `suspend_d` / 涨跌停封板），实测矛盾 0 条（见 `database/status.py::audit_coverage`） |
| **天花板** | 日内停牌时段的开盘/收盘价可能不代表真实可成交价，但我们无从分辨 |
| **扩展需要** | 分钟级 K 线 + `suspend_timing` 时间段对齐，就能精确判断"某分钟能不能交易" |
| **现在要不要做** | 不需要。日内停牌占比 0.5%，且方向影响有限。 |

### P4 · 复牌首日的"无涨跌幅"判定是经验阈值（对应 C4b）

| | |
|---|---|
| **痛点** | "长期停牌复牌首日不设涨跌幅"的**阈值是经验性的**（取"错过 ≥11 个交易日"），不是查到的交易所条文 |
| **日线天花板** | 判定复牌只能靠"相邻两根 K 线之间市场开了几天而它没有"，这已经是日线能给出的最精确信号 |
| **日线下已做** | 数据驱动定阈值：错过 1–5 个交易日越界率 0.00%（明确有限制）、6–10 日 3.47%（混合带）、11–20 日 48.63%（明确无限制）。取 11（证据最硬的区间），并把不确定性登记进 `database/defects.py` |
| **天花板** | 6–10 日那个混合带无法从日线数据分辨是"复牌免限"还是"就是涨得多" |
| **扩展需要** | 停复牌公告的**原因**（重大资产重组/股改/一般事项）—— 这不是分钟数据问题，而是**事件数据**问题。有公告文本或事件标签即可，与数据频率无关 |
| **现在要不要做** | 不需要。已登记为经验性缺陷，方向影响有限（该免限的日子被多拦，偏保守）。 |

### P5 · 执行摩擦只能给区间（对应 ① 排队建模）

| | |
|---|---|
| **痛点** | 日线下的冲击/滑点模型（平方根冲击等）都是**横截面经验公式**，参数是校准出来的 |
| **天花板** | 无法验证"这一笔委托实际会以什么价成交" |
| **日线下已做** | 冲击模型已接进所有组合路径（默认 `fixed` + 1bp，可切 `sqrt`） |
| **扩展需要** | 分钟级成交量分布 + 盘口深度 |
| **现在要不要做** | 不需要。当前的做法（可配置参数 + 容量敏感性分析）已经是日线下的合理上限。 |

---

## 一条通用原则

上面 5 条有个共同结构：

```
日线能表达的  →  已经做了
日线不能表达的 →  ① 量化它的大小（埋点/敏感性）
                 ② 在报告里写死声明（方向 + 是上界还是下界）
                 ③ 登记进 database/defects.py（让人看得到）
```

**不要为了"更准"而在日线上堆越来越复杂的近似** —— 那会把"已知的近似"
变成"未知的拟合"，反而更危险。日线平台的可信度来自**误差被标注清楚**，
不是来自误差被消灭。

## 未来扩展时的结构准备（现在不做，只记着）

真要上分钟级，这几处是天然的接入点（**当前不要为它们做多余抽象**）：

| 位置 | 现在 | 扩展时 |
|---|---|---|
| `execution/market_rules.py` | "不可成交"二元判定 | 按队列位置部分成交 |
| `backtest/multi_engine.py::fill_timing` | `next_open` / `same_close` | 信号时刻 → 下一分钟 |
| `database/status.py` | 全天/日内停牌二元 | `suspend_timing` 与分钟对齐 |
| `analytics/result_report.py` | 被拦委托汇总 | 加成交价偏离分布 |
| 数据层 | `year=Y/{code}.parquet`（日线） | 需要新的分区层级（频率维度） |

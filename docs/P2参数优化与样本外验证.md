> 新增 `optimizer/` 包与 `scripts/optimize.py`。
> P2 清单里的另外三项（因子库、事件循环、数据层原子写）见文末「尚未实现」。

---

## 一、为什么先做这个

项目原来的"多策略对比"是把 11 个策略在同一段历史上各跑一遍、**按夏普排序**：

```
   MeanRev  0.354150  3.440050 13.811571 ...
     BBand  0.138469  2.229480 33.128058 ...
```

这已经是数据窥探（data snooping）的温和版本——你在 11 个结果里挑了最好看的那个。
参数优化会把这个问题放大几百倍：试 300 组参数、挑夏普最高的那组，
得到的"夏普 3.4"很可能只是噪音。

**Walk-Forward 是解决它的标准手段**：用前一段数据选参，在紧接着的、
没参与选参的数据上验证，滚动前进，最后只看拼接出来的样本外表现。

## 二、实测结论（最重要的部分）

`000001 / 600519 / 300750`，2019-2024，MA 策略，随机搜索 `fast∈[2,20] slow∈[20,120]`，
训练 252 日 / 测试 63 日，每窗 12 组参数，19 个滚动窗口：

| 代码 | 窗口数 | **样本内夏普** | **样本外夏普** | **过拟合落差** | 样本外总收益 | 样本外回撤 |
|---|---:|---:|---:|---:|---:|---:|
| 300750 | 19 | 1.434 | 0.128 | **1.306** | +47.60% | -22.00% |
| 600519 | 19 | 0.851 | -0.167 | **1.018** | -4.66% | -14.44% |
| 000001 | 19 | 0.331 | -0.471 | **0.802** | -32.32% | -33.11% |

**样本外夏普为正的标的：1/3。**

单看 `000001` 的某个窗口最典型：

```
W1  训练 2019-04-09~2020-04-20 → 测试 2020-04-21~2020-07-23
    最佳参数 fast=5, slow=29     IS 夏普 = 0.003
    ... 同一组参数在测试段的夏普 = -3.03
```

也就是说：**在训练段挑出来的"最佳参数"，到样本外经常直接翻负**。
这正是参数优化的真实风险，也是这次实现的价值所在。

## 三、用法

### 1) 网格搜索 / 随机搜索

```powershell
# 网格（参数少、范围窄）
python scripts/optimize.py --symbol 000001 --strategy MA \
    --grid fast=3,5,10,20 slow=20,30,60,120 --top 10

# 随机（参数多、范围大时更有效）
python scripts/optimize.py --symbol 000001 --strategy MA \
    --random fast=2:20 slow=20:120 --n-iter 60 --objective sharpe
```

参数空间写法：`fast=5,10,20`（离散）、`fast=2:20`（整数区间）、`k=0.1:1.0`（浮点区间）。
可用目标：`sharpe`（默认）/ `total_return` / `annual_return` / `calmar` / `profit_factor` / `win_rate` / `max_drawdown`。

> ⚠️ 这两种搜索**都会在结尾打印数据窥探警告**，明确告诉你试了多少组、最优比中位数好多少。

### 2) ★ Walk-Forward 样本外验证（推荐）

```powershell
# 单标的
python scripts/optimize.py --symbol 000001 --strategy MA \
    --random fast=2:20 slow=20:120 --walk-forward \
    --train-days 252 --test-days 63 --n-iter 30

# 多标的（更能说明策略是否稳健）
python scripts/optimize.py --symbols 000001,600519,300750 --strategy MA \
    --random fast=2:20 slow=20:120 --walk-forward --n-iter 12 --out result.csv

# 训练段逐窗扩张（anchored）而非固定长度滚动
python scripts/optimize.py --symbol 000001 --strategy MA \
    --random fast=2:20 --walk-forward --anchored
```

输出包含：

```
  窗口数            : 19
  每窗训练/测试     : 252 / 63 交易日
  测试段有交易的窗口: 4/19   ← 多数窗口没触发信号，样本外结论参考价值有限
  每窗尝试参数组数  : 12

  样本内(IS) 平均夏普:    0.331   ← 选参时看到的表现
  样本外(OOS) 平均夏普:  -0.471   ← 真实拿到的表现
  过拟合落差        :    0.802   落差明显，参数很可能在拟合噪音

  —— 拼接后的样本外业绩（唯一诚实的结果）——
    总收益率  :  -32.32%
    年化收益率:   -7.90%
    夏普比率  :    -1.61
    最大回撤  :  -33.11%

  —— 各窗口选出的参数（越集中越稳定）——
    fast        : 11×5, 3×4, 5×3, 12×3, 10×1, 15×1
    slow        : 98×4, 57×4, 29×2, 118×2, 106×1, 96×1
```

**四个关键读数**：

| 读数 | 含义 |
|---|---|
| 样本内 vs 样本外 落差 | 落差越大越可能过拟合；<0.3 稳健，>1.0 几乎可以断定过拟合 |
| 拼接后的样本外业绩 | **唯一诚实的结果**——各测试段用各自训练段选出的参数、首尾相接连成 |
| 参数稳定性 | 各窗口选出的参数越集中越可信；每窗都不一样说明在拟合噪音 |
| 测试段有交易的窗口数 | 若多数窗口根本没成交，样本外结论的参考价值就要打折 |

## 四、实现要点

```
optimizer/
├── search.py       参数空间（离散/区间）、笛卡尔积、随机采样、网格/随机搜索
└── walkforward.py  窗口切分、滚动选参、样本外拼接、过拟合落差、参数稳定性
```

- **窗口切分**：默认 `step = test_days`，测试段首尾相接连成完整的样本外区间，互不重叠；
  `anchored=True` 时训练段起点固定、逐窗扩张。
- **选参只用训练段**：每个窗口重新搜索，参数不跨窗口复用。
- **样本外拼接**：各测试段净值归一化后按链式相乘，得到连续曲线；
  末值即"如果一直按 walk-forward 方式运行"的累计收益。
- **不依赖 `scripts/`**：`optimizer/` 只依赖 `backtest` / `execution`，
  策略通过 `factory(params) -> Strategy` 注入，因此可以脱离 CLI 单独使用。
- **指标在完整序列上预计算后再切片**：因现有指标（SMA/EMA/RSI/ATR/布林带）
  全部是因果的（只用历史），测试段第一根 bar 用到训练段末尾的数据是符合现实的。

## 五、顺带修掉的一个真 bug

多标的汇总时发现 `000001` 结果是空的，日志显示：

```
!! 1 失败: ValueError: 1 数据库无数据
```

**根因**：在 PowerShell 里 `--symbols 000001,600519,300750` 会被解析成**数组**，
元素被转成整数 → `000001` 变成 `1`，查不到数据。

**修复**：`parse_symbols()` 统一按 6 位补零，并兼容逗号 / 空白 / 分号分隔。
在 PowerShell 下手写多标的时建议加引号或改用分号：

```powershell
python scripts/optimize.py --symbols "000001;600519" --strategy MA --walk-forward ...
```

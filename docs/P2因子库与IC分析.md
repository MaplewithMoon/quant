# P2 因子库与 IC 分析

> 新增 `factors/` 包与 `scripts/factor_eval.py`。
> 这是从"11 个写死的策略"走向**因子研究**的关键一步。

---

## 一、解决了什么问题

原来判断"某个信号有没有用"，只能把它写成策略、跑一遍回测、看收益曲线。
这有三个毛病：

1. **没法横向比较**：不同策略的收益受仓位管理、择时、参数影响，不纯粹反映信号本身
2. **样本太少**：一只股票 4 年只有 ~1000 个观测
3. **容易自欺**：曲线好看可能只是运气

因子研究把它换成标准问题：**横截面上"因子值高的股票，未来收益是否更高"**。
一天有 300~5000 个横截面观测，4 年就是几十万个样本，统计上可靠得多。

## 二、实现结构

```
factors/
├── panel.py       横截面面板构建（DuckDB 直读 parquet）+ 前瞻收益
├── base.py        因子定义与注册表（@register 装饰器）
├── library.py     18 个内置因子
└── evaluation.py  IC / RankIC / ICIR / 分层 / 换手 / 衰减
```

### 面板构建为什么用 DuckDB

`database.loader` 是"单股票、单数据集"接口，拼一个 300 只股票的面板要循环 300 次读文件。
这里直接对 parquet 分区做一次聚合查询，只读需要的列：

```
面板: 726 个交易日 × 300 只股票     （2022-2024，含复权价与估值）
```

### 复权处理

因子（动量/波动率）必须建立在**复权价**上，否则除权日的暴跌会被当成真实收益。
面板 join `frozen/adjust` 的 `adj_factor` 得到后复权价（`close × adj_factor`），
后复权与"收益率"口径一致。

### 无未来函数的保证

- 因子只用当日及以前的数据（rolling/expanding）
- 前瞻收益 `fwd(t) = close(t+1+N)/close(t+1) - 1`，**从 t+1 起算**，与因子不重叠
- 有一条测试专门守这个：**改写未来数据后，历史因子值必须逐点不变**

自定义因子只需一个装饰器：

```python
from factors.base import register

@register("my_alpha", "我的因子", direction=1, category="自定义")
def my_alpha(panel):
    c = panel["close_adj"]
    return c / c.shift(30) - 1      # 只用当日及以前的数据！
```

### 结论解读

1. **低波动类因子（`vol_60`/`amp_20`/`vol_20`/`max_ret_20`）最显著**，t 值都在 -4 以上。
   方向都是"小→多"，即**低波动股票后续表现更好** —— 与低波异象一致。
2. **`bp`（账面市值比）是最干净的因子**：IC +0.036、t +4.51、**单调性 1.00**、
   换手仅 3.2%、且均值与中位数方向一致。低换手意味着交易成本压力小。
3. **`turn_20`（换手率）值得关注**：IC -0.040、t -3.92，而换手仅 3.8% —— 
   低换手 + 有预测力，是成本效率最高的组合。
4. **`mom_20` 基本无效**（IC -0.007, t -0.80）。A 股中短期动量弱、反转特征更强，
   这与市场共识一致。而 `mom_120` 略正（IC +0.008）但也不显著。
5. **换手率差异极大**：`vol_ratio_20` 换手 64%、`rev_5` 49%，而 `size`/`sp` 只有 2.3%。
   同样的 IC，换手高的因子实盘会被成本吃光。

## 五、一个重要的方法论陷阱（本模块主动检测）

### 算术均值分层 与 秩 IC 会符号相反

初版只用"分层算术均值"展示结果时，出现了矛盾：

```
vol_60  分层算术均值:  Q1 0.047%  Q2 0.046%  Q3 0.050%  Q4 0.054%  Q5 0.093%
        但 IC 均值 = -0.0465（高波动 → 低收益）
```

Q5（最高波动）的均值反而最高，与负 IC 直接矛盾。

**根因**：个股收益分布**右偏**（偏度 0.7~1.0），而**高波动组的右尾更肥**。
少数暴涨把算术均值拉高，但秩相关仍是负的。用中位数验证即可看清：

| 分层 | 算术均值 | **中位数** | 偏度 |
|---|---:|---:|---:|
| Q1（低波动） | 0.0472% | **0.0000%** | 0.87 |
| Q2 | 0.0457% | **-0.1036%** | 0.92 |
| Q3 | 0.0498% | **-0.1768%** | 0.98 |
| Q4 | 0.0539% | **-0.1918%** | 0.80 |
| Q5（高波动） | 0.0926% | **-0.2244%** | 0.70 |

**中位数随波动率单调下降**，与负 IC 完全一致 → 是右偏造成的假象，不是计算错误。

对比 `bp`：算术均值与中位数**都**单调递增（0.019%→0.066% / -0.227%→0.000%），
与正 IC 一致 ✓

**处理方式**：本模块默认同时输出均值与中位数分层，并在两者方向相反时**主动告警**：

```
⚠️ 有 12 个因子的「算术均值分层」与「中位数分层」方向相反: vol_60, amp_20, ...
   原因：个股收益右偏，高波动组右尾更肥，等权算术均值被少数暴涨拉高。
   这类因子应以秩 IC / 中位数为准，不要直接按均值下结论。
```

> 18 个因子里有 12 个存在背离 —— 这说明**只看分层均值是很容易被误导的**。

## 六、用法

```powershell
# 列出所有因子
python scripts/factor_eval.py --list

# 评估单个因子（输出完整报告：IC / 分层 / 换手 / 衰减）
python scripts/factor_eval.py --factor bp --start 2022-01-01 --end 2024-12-31 --limit 300

# 批量评估（按 |IC| 排序，含均值/中位数一致性标记）
python scripts/factor_eval.py --all --start 2022-01-01 --end 2024-12-31 --limit 300 --out factor.csv

# 自定义持有期与分层数
python scripts/factor_eval.py --factor turn_20 --periods 5 --quantiles 10
```

编程式：

```python
from factors import load_panel, get_factor, evaluate, list_factors

panel = load_panel("2022-01-01", "2024-12-31", limit=300)
rep = evaluate(get_factor("bp"), panel, periods=1, n_quantiles=5)
print(rep.summary())
rep.quantile["多空"].cumsum().plot()      # 多空累计收益
print(rep.mean_median_diverges())          # 均值/中位数是否背离
```

## 八、尚未实现

1. **因子持久化**：当前每次现场计算（300 只 × 726 天 ≈ 1 分钟）。因子数超过 50
   或股票池超 3000 时应落盘到 `cleaned/factor_*/`，配方登记进 `RECIPES`。
2. **行业/市值中性化**：当前因子值未做中性化，因子间暴露高度相关
   （如 `vol_20` 与 `size` 天然相关），合成前应先正交化。
3. **因子合成**：暂无等权/IC 加权/最大化 ICIR 的合成器。
4. **股票池仍用"区间内日均成交额前 N"**：这是探索期的简化，
   正式研究应用 `frozen/index_cons` 的**历史成分**并剔除 ST/停牌（存在幸存者偏差）。
5. **未接组合构建**：IC 与分层只说明因子有预测力，
   要变成可交易的组合还需要权重方案、约束与交易成本 —— 见路线图阶段一。

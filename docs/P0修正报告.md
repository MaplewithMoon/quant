## 一、修正了什么

| # | 缺陷 | 根因位置 | 修正 |
|---|---|---|---|
| 1 | **双账本**：对外报出的净值与账户真实总资产不一致 | `scripts/backtest.py` 的 `build_equity_curve()` 用成交记录重推现金与持仓，与 `engine.portfolio` 各算一套 | 引擎逐 bar 快照权益（`BacktestEngine.equity_curve`），删除 `build_equity_curve`，指标直接消费唯一账本；新增 `ledger_gap` 不变量，引擎自检并报错 |
| 2 | **卖出佣金符号反了**：往返手续费净额≈0 | `broker.execute` 把佣金累加进 `Order.filled_amount`，引擎又用 `filled_amount/filled_qty` 当成交价 → 卖出时佣金被当作收入加回现金 | `Order` 增加独立的 `commission` 字段与 `avg_fill_price`/`buy_cost`/`sell_proceeds`，费用与成交额彻底分列 |
| 3 | **胜率分母含零盈亏买入行** | `backtest/metrics.py` 用全部成交行做分母，而买入行 `pnl` 恒为 0 | 只在"已平仓"（sell）行上统计胜率 / 盈亏比 / 交易次数 |
| 4 | **静默缩量**：成交记录与真实持仓脱钩 | `Portfolio.buy` 现金不足时偷偷改小 `size`，引擎仍按原始委托量写记录 | `Portfolio.buy` 现金不足直接抛 `ValueError`；下单量改由 `SimulatedBroker.max_affordable_size()` **事先算准** |
| 5 | 顺带：`Position.unrealized_pnl_pct` 把股数乘了进去 | `portfolio/portfolio.py` | 改为纯比率 |

## 二、修正前后数据实例对照

**同一输入**：`000001`，2024-01-01 ~ 2024-12-31（242 根日线），策略 `MA(5,20)`，
初始资金 1,000,000，佣金万 1，滑点 0.1%。

### 缺陷 1：双账本

| 项目 | 修正前 | 修正后 |
|---|---:|---:|
| 对外报出的净值曲线末值 | 1,030,567.10 | 1,038,113.99 |
| 账户真实总资产 | 1,040,192.63 | 1,038,113.99 |
| **两者差额（应 = 0）** | **9,625.54** | **0.00** |
| 引擎逐 bar 权益点数 | 无（引擎不产权益曲线） | 242 |

> 修正前账户里明明有 1,040,192.63，报告却写 1,030,567.10 —— 所有对外指标都取自后者。

### 缺陷 2：费用记账

| 项目 | 修正前 | 修正后 |
|---|---:|---:|
| 成交表是否有 `commission` 列 | 否 | **是** |
| 累计手续费 | 无法从成交表看出 | **2,282.60** |
| 已实现盈亏（扣费后） | 无此字段 | **36,740.88** |
| 首笔买入价 | `7.980798` ← 混入了佣金 | **`7.980000`** ← 干净成交价 |

修正后的买入价可复核：`round(7.9763 × (1 + 0.001), 2) = 7.98` ✅

### 缺陷 3：静默缩量（微探针直接验证）

对 `Portfolio.buy` 传入旧引擎算出的委托量 125,371 股（价格 7.980798）：

| | 修正前 | 修正后 |
|---|---|---|
| 是否报错 | 否 | **抛 `ValueError`** |
| 返回/实际股数 | **125,300**（悄悄少了 71 股） | 拒绝成交，现金不变 |
| 成交记录 vs 持仓 | 记录 125,371 / 实持 125,300 ❌ | 先算准 125,300 → 记录 125,300 / 实持 125,300 ✅ |

修正后 `max_affordable_size(1,000,000, 7.9763) = 125,300`，**下单前就确定**，不再有"事后缩量"。

### 缺陷 4：胜率

| 项目 | 修正前 | 修正后 |
|---|---:|---:|
| 报出的胜率 | **19.05%** | **40.00%** |
| 分母 | 全部成交行 21 行 | 平仓笔数 10 笔 |
| 分子 | 4 笔盈利 | 4 笔盈利 |

### 对外指标变化（差异全部来自口径，策略与数据完全未变）

| 指标 | 修正前 | 修正后 |
|---|---:|---:|
| 总收益率 | 3.06% | 3.81% |
| 最大回撤 | -16.25% | -15.80% |
| 交易次数 | 10 | 10 |
| 盈亏比 | 1.2241 | 1.2107 |

修正后总收益**更高**，是因为修正前那本"重推的净值曲线"自身有 bug
（循环从第 1 根 bar 开始，丢掉第 0 根的成交；卖出时用含佣金的价格虚增现金）；
而修正前的账户侧又因"佣金被退回"虚高。两处偏差方向不同，最终报出的数字
**既不是账户真实值，也不是正确值**。

## 三、新增的回归测试（防止再次跑偏）

`tests/test_ledger.py` —— 8 项账目不变量，用 `pytest` 或 `python scripts/run_tests.py` 都会跑：

| 测试 | 守住的不变量 |
|---|---|
| `test_equity_curve_equals_portfolio` | 净值曲线末值 == 账户总资产（`ledger_gap < 1e-6`）、每 bar 都有快照 |
| `test_no_trades_equity_is_flat` | 不交易时净值恒为初始资金（旧实现会跟随市场涨跌） |
| `test_round_trip_costs_money` | 价格不变时，往返亏损 **恰好等于**两笔手续费 |
| `test_commission_sign_on_sell` | 卖出净收入 = 成交额 − 费用（费用是减项） |
| `test_cash_non_negative_and_no_silent_shrink` | 现金非负；成交记录股数 == 实际持仓 |
| `test_buy_rejects_insufficient_cash` | 现金不足必须报错且不改动现金 |
| `test_win_rate_uses_closed_trades_only` | 胜率分母 = 平仓笔数 |
| `test_position_pct_is_a_ratio` | 未实现收益率是"率"而非被股数放大 |

其中 `test_round_trip_costs_money` 在**修正前的代码上必然失败**（往返亏损为 0），是这次修正最直接的守门测试。

`tests/test_engine.py::test_commission_min` 也一并修正：旧断言用
`filled_amount - turnover` 反推费用，等于把"佣金混进成交额"这个 bug 当成了规范。

## 六、尚未处理的（P1，属执行模型而非账目）

本次只修**账目正确性**。以下仍缺失，会让回测仍偏乐观：

1. **T+1**：当日买入当日即可卖
2. **涨跌停约束**：涨停不可买、跌停不可卖（`db/cleaned/limit_price` 数据已就绪，引擎不读）
3. **停牌约束**：停牌日不应成交
4. **一手 100 股取整**：实测 20/21 笔成交股数不是 100 的整数倍
5. **印花税 / 过户费**：目前只有佣金
6. **成交时点**：仍是"第 i 根 bar 收盘决策 + 第 i 根 bar 收盘成交"（存在未来函数嫌疑），应改为 `next_open`
7. **同 bar 收盘成交** + 策略可访问整张 DataFrame → 未来函数通道未封堵

这些建议在撮合层集中实现（新增 `execution/market_rules.py`），并复用已就绪的
`db/cleaned/limit_price`、`db/frozen/suspend`、`db/frozen/st`。

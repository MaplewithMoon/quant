# 聚宽策略移植报告

> 把用户引入的两份聚宽（JoinQuant）策略移植到本项目，在 **2024-01-01 ~ 2025-12-31**
> 区间回测，用于与聚宽平台的结果对照、验证本项目架构的正确性。
>
> 移植原则：**策略主体一行不改**，只把 `from jqdata import *` 换成本项目的
> `from joinquant import *`。这样回测差异只可能来自**数据**与**撮合**，便于逐项归因。

## 一、结论先行

| 项 | 结果 |
|---|---|
| 移植方式 | 策略代码逐行保留，只替换 import（`scripts/port_joinquant.py` 自动生成） |
| 覆盖的聚宽 API | 约 40 个（调度 / 上下文 / 行情 / 财务 query DSL / 下单 / 设置 / 日志） |
| 撮合与账本 | **复用本项目自己的** `Portfolio` / `SimulatedBroker` / `MarketRules`，不另起一套 |
| 策略异常 | 0（调试期共修掉 6 个兼容性缺陷，见第五节） |
| 主要差异来源 | 指数成分为规则重建、ETF 用现金合成、分钟撮合用日线近似 |

**先用本文第四节的「近似与差异」清单核对，再去看净值差异** —— 否则很容易把
"数据口径不同"误判成"引擎算错了"。

## 三、兼容层设计

```
joinquant/
├── data.py     JQData：行情/财务/指数/ETF 的本地实现 + pandas 1.x 兼容
├── api.py      API 表面（g / context / 下单 / 调度 / query DSL）+ 事件循环
└── __init__.py 导出，使 `from joinquant import *` 等价于 `from jqdata import *`
strategies/jq/
├── guojiu_smallcap.py       v1 移植版（372 行，主体与原版逐行一致）
└── guojiu_smallcap_v2.py    v2 移植版（405 行）
scripts/port_joinquant.py    自动生成移植文件
scripts/jq_backtest.py       回测 CLI
tests/test_joinquant.py      17 项测试
```

### 3.1 事件循环

逐交易日、按时间顺序执行 `run_daily` / `run_weekly` 注册的任务：

```
09:05  prepare_stock_list     （读昨日涨停、判断是否可交易日）
10:00  sell_stocks / time_choosing
10:01  position_adjustment
10:05  check_remain_amount
14:00  trade_afternoon        （涨停开板卖出、余额补买）
14:50  close_account          （空仓月清仓）
```

- `run_weekly(func, N)`：`N` = **每周第 N 个交易日**（不是"周 N"）。
  2024-01-01 是元旦，那一周第 2 个交易日是 **1 月 3 日（周三）**，有测试覆盖。
- 单个任务抛异常**不终止回测**（与聚宽一致），但会记进「拒绝委托」并带 traceback。

### 3.2 撮合复用本项目执行层

JQ 的 `order_target_value` → 本项目的 `Portfolio.buy/sell` + `SimulatedBroker` + `MarketRules`：

| 聚宽语义 | 本项目实现 |
|---|---|
| `order_target_value(code, v)`，按手取整 | `max_affordable_size` / `sellable_size`，`lot_size=100` |
| T+1（当日买入当日不可卖） | `Portfolio.new_day()` + `sellable_size()` |
| 涨停买不进 / 跌停卖不掉 | `MarketRules.check_buy / check_sell`（封板口径） |
| 佣金 / 印花税 / 最低佣金 | 按策略自己的 `OrderCost` 传入 |
| 滑点 | `FixedSlippage(x)` / `PriceRelatedSlippage(x)` → 本项目单边 = **x/2**（聚宽口径是双边） |

## 四、近似与差异（对照聚宽前必读）

| # | 项 | 聚宽 | 本项目 | 影响方向 |
|---|---|---|---|---|
| 1 | **成交时点** | 分钟级撮合（10:00 的单 10:00 成交） | 只有日线：上午任务用**当日开盘价**，下午（14:00/14:50）用**当日收盘价**（`--fill auto`） | 买卖价有系统性差异，是**最主要的偏差来源** |
| 2 | **399101 成分股** | 中小综指真实成分 | 规则重建：**002/003 开头** | 成分略有出入 |
| 3 | **399101 点位** | 官方指数 | 重建成分股的**等权**日收益合成 | 用于 MA10 择时，等权与市值加权会有差异 |
| 4 | **000985 成分股** | 中证全指真实成分 | 规则重建：**全部 A 股**（含北交所？本库不含） | 影响 v2 的选股池边界 |
| 5 | **511880 ETF** | 真实日线 | **合成现金等价物**（年化 2%，`--etf-yield`） | 空仓期收益被略微低估 |
| 6 | **v2 择时指数** | 微盘股指数 `tiny_index.csv` | 改用 `399101.XSHE`（代码自带分支） | **行为改变**，择时点会不同 |
| 7 | **分钟线** | `history(1,'1m')` 真实分钟价 | 近似为**当日开盘价** | 涨跌停判断与"当前价"有偏差 |
| 8 | **财务数据** | 聚宽 `get_fundamentals` | 本库利润表，**按 ann_date 做 PIT 对齐** | 口径一致；个别字段映射见下 |
| 9 | **审计意见筛选** | 可选 | 未实现（`g.filter_audit = False`，两策略默认关闭） | 无影响 |
| 10 | pandas 版本 | 1.x | 3.x | 已用 `LegacySeries` 补回整数位置索引语义 |

字段映射：`np_parent_company_owners → n_income_attr_p`、`net_profit → n_income`、
`operating_revenue → revenue`、`valuation.market_cap(亿元) → total_mv(万元)/1e4`。

## 五、移植中修掉的 6 个兼容性缺陷

这些**都不是策略逻辑问题**，而是"聚宽 API → 本地实现"的落差；每一个都会让策略
静默不交易，所以必须逐个消掉才有对照价值。

| # | 问题 | 症状 | 修法 |
|---|---|---|---|
| 1 | **pandas 3 移除了整数索引的位置回退** | `last_prices[stock][-1]` 抛 `KeyError: -1`，v1 的 84 次调仓全挂。聚宽跑的是 pandas 1.x，`s[-1]` 是位置索引 | 提供 `LegacySeries`，整数键找不到标签时回退到 `iloc` |
| 2 | **`context.portfolio.positions` 不是普通 dict** | 聚宽对未持仓代码返回 0 持仓对象，策略写的是 `positions[stock].total_amount == 0`；普通 dict 直接 KeyError（506 次拒绝） | 用带 `__missing__` 的 `_Positions` |
| 3 | **`get_price` 不支持指数/ETF** | `get_price('399101.XSHE')` / `get_price('511880.XSHG')` 抛 KeyError —— 它们不在股票面板里 | 增加 `any_close()`：股票走面板、指数走重建、ETF 走合成 |
| 4 | **`get_price` 的 1 分钟分支方向搞反** | `current_bar()` 返回的是「字段 × 代码」，按「代码 × 字段」取列 → `KeyError: 'open'`（8 次） | 改成按字段行取 |
| 5 | **`query` DSL 漏取过滤字段** | 策略写 `query(valuation.code).filter(income.operating_revenue > 1e8)`，只按 SELECT 取数会让过滤条件**被静默跳过**，把不合格的股票放进来 | 取数列 = SELECT ∪ WHERE |
| 6 | **基准序列只取了 1 个点** | `index_close(..., count=1)` 导致组合与基准没有重叠交易日，画图直接报错 | 取全序列 |
| 7 | **`initialize` 里看到的日期是面板首日** | 面板为预热多带一年多历史，`context.current_dt` 指向预热期，策略在 `initialize` 里算出的 `g.trading_day` 落在 2022 年 → 整个回测一次都不调仓 | `run()` 在调用 `initialize` 前先把 `current_dt` 设成**回测起始日** |
| 8 | **`get_trade_days` 返回 Timestamp** | 策略比较 `today == g.trading_day`，其中 `today` 是 `datetime.date`；`Timestamp == date` **恒为 False**，调仓日永远不成立，v2 全程持 ETF（波动 0.02%） | 返回 **`datetime.date` 列表**（聚宽口径） |

另外两处体验问题：异常只记 `KeyError` 不带 key 和行号（现已带 traceback 与 `@文件:行号`）；
`_Positions` 访问未持仓不应写入字典（有专项测试）。

## 六、回测结果

> 区间 2024-01-01 ~ 2025-12-31，本金 10 万，成交价 `auto`（上午用开盘、下午用收盘），
> A 股制度约束开启。
>
> **数据已换成真实值**：399101/000985 用真实指数日线与真实月度成分，
> 511880 用真实 ETF 日线（见下载脚本 `scripts/download_index_extra.py`）。

### 6.1 真实数据 vs 旧的规则重建

| | 旧（规则重建 / 合成） | **新（真实数据）** |
|---|---|---|
| v1 累计收益 | +119.83% | **+121.27%** |
| v1 夏普 | +1.432 | **+1.412** |
| v1 最大回撤 | −21.26% | **−17.83%** |
| v1 基准（399101） | +37.45%（等权重建） | **+37.80%（真实指数）** |
| v2 累计收益 | +232.91% | **+257.42%** |
| v2 夏普 | +2.658 | **+2.731** |
| v2 最大回撤 | −15.04% | **−11.35%** |
| v2 基准（000985） | +39.29%（"全部 A 股"近似） | **+34.81%（真实中证全指）** |

换成真实数据后**结论不变**，差异都在可解释范围内：
- v1 的回撤改善 3.4pp，主要来自择时指数从"等权重建"换成真实中小综指点位
- v2 的基准降了 4.5pp（"全部 A 股"确实高估了中证全指），但策略收益反而升了 24.5pp
- 511880 换成真实价格后变成近似零收益（见 6.3）

### 6.2 最终结果

| 策略 | 累计收益 | 年化 | 波动 | 夏普 | 最大回撤 | 基准年化 | Alpha | Beta |
|---|---|---|---|---|---|---|---|---|
| **v1** 中小综指 + 动态持股 + 周调仓 + 止损 | **+121.27%** | +51.21% | 33.24% | **+1.412** | **−17.83%** | +18.17% | +34.35% (t=1.61, p=0.109) | +0.646 |
| **v2** 中证全指 + 固定 15 只 + 月调仓 + 择时 | **+257.42%** | +94.10% | 25.51% | **+2.731** | **−11.35%** | +16.82% | +58.83% (t=3.74, p=0.000) | +0.602 |

期末权益：v1 22.13 万、v2 36.39 万（本金 10 万），各 485 个交易日。

### 6.3 ⚠️ 关于 511880（银华日利）的口径陷阱

下载真实日线后发现一个**反直觉的事实**：511880 是**货币 ETF，价格恒在 100 附近**，
收益靠"份额折算"发放而不是价格上涨 —— 2024-2025 真实价格累计只有 **−0.036%**，
而原先按"年化 2% 现金等价物"合成是 **+4.0%**，相差 4 个百分点。

- **经济上**：合成口径更准（拿到了货币收益）
- **对照聚宽时**：应当用**真实价格** —— 聚宽回测同样不处理份额折算，
  它的 ETF 持仓也近似零收益

当前实现是**优先真实日线**，所以现在与聚宽口径一致。
若要看"经济上正确"的版本，把 `joinquant/data.py` 的 `etf_close` 改回合成即可。

### 6.5 已知限制

| 项 | 说明 |
|---|---|
| **成交价为日线近似** | 上午任务用开盘、下午（14:00/14:50）用收盘；聚宽是分钟撮合。这是与聚宽差异的**首要来源** |
| **末尾 2 次调仓取不到日期** | v2 在回测最后会找"下个月的第一个交易日"，超出面板覆盖范围 → `IndexError`，那 2 期不调仓。试过改用交易所日历（覆盖到 2027）反而让策略状态机卡死，故保持用面板日期 |
| 微盘股指数 | 万得指数 tushare 没有，v2 仍用代码自带的 `399101.XSHE` 分支 |

### 与聚宽对照的建议步骤

1. **先核对基准**：本项目重建的 399101 / 000985 等权指数在 2024-2025 的累计收益，
   与聚宽上同区间官方指数是否接近（本次重建值分别为 +37.45% / +39.29%）。
   基准差得多，说明是指数重建的问题，不用往下查。
2. **再核对交易次数与时间**：`results/jq/equity_*.csv` 有逐日净值，
   聚宽导出成交明细后可比对**首次建仓日、调仓日、每期持股数**。
   如果调仓日错位，多半是 `run_weekly(…, 2)` 的"第 2 个交易日"理解差异。
3. **最后比净值**：在 1、2 都对得上的前提下，剩余差异应能由第四节第 1 条
   （成交时点：分钟撮合 vs 日线开盘/收盘）解释。可以把 `--fill open` /
   `--fill close` 各跑一遍，看哪一端更接近聚宽，从而定位成交价的系统偏差。

### 敏感性与对照开关

```bash
--fill open|close     # 成交价口径
--etf-yield 0.0       # 把货币 ETF 当作零收益现金
--no-rules            # 关闭 T+1 / 涨跌停封板等制度约束（用于判断约束的影响）
--verbose             # 打印策略日志（含每期选股与买卖）
```

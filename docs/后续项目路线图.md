### 阶段二：生产化

**目标**：让这套东西能"每天自己跑"，且出错能被发现。

| # | 交付物 | 验收标准 |
|---|---|---|
| 2.1 | **数据更新调度** | `daily_update.py` 可由 Windows 计划任务触发；交易日历驱动（非交易日不跑）；失败重试 + 失败清单 + 非零退出码 |
| 2.2 | **数据质量门禁** | `validate_data.py` 返回非零退出码；关键校验（覆盖率突降、主键重复、价格越界）失败即告警 |
| 2.3 | **HTML 回测报告** | 一条命令产出静态 HTML：净值曲线 + 回撤 + 持仓热力图 + 指标表 + 归因表 + 因子暴露 |
| 2.4 | **策略/因子快照与版本** | 每次回测记录：代码 commit、数据 `_meta.json` 时间戳、参数、结果 hash；可回答"这条曲线是哪个版本跑出来的" |
| 2.5 | **告警** | 数据更新失败 / 回测异常 / 风控触发 时推送到（邮件/企业微信/Server酱，任选） |

**阶段验收**：连续 20 个交易日无人值守自动更新，数据校验全过，每日自动产出报告；
人为制造一次下载失败，能被告警捕获且次日自动补上。

### 阶段三：实盘对接

**目标**：把回测**同一套**策略代码跑到真实账户上。

| # | 交付物 | 验收标准 |
|---|---|---|
| 3.1 | **`live/` 交易日循环** | 与回测共用 `Strategy` / `RiskManager` / 组合构建，**不复制逻辑**；收盘后算信号、次日开盘下单 |
| 3.2 | **仿真盘（paper trading）** | 用真实行情 + 模拟成交跑满 1 个月，与同期回测偏差可解释（滑点/成交差异） |
| 3.3 | **券商网关** | 对接旁边的 `方正证券FQT交易客户端`（或先接 QMT/Ptrade）；下单/撤单/查持仓/查成交回报 |
| 3.4 | **对账与风控** | 每日收盘对账（系统持仓 vs 券商持仓），不一致即停；盘中止损/熔断 |
| 3.5 | **幂等与可恢复** | 下单前查当日委托，避免重复下单；程序重启能从状态文件恢复 |

**阶段验收**：仿真盘连续 1 个月与回测偏差 < 1pp，对账 0 差异。

> ⚠️ 顺序不能颠倒：**没有阶段一的组合构建 + 阶段二的对账，不要碰真实资金。**

## 四、优先级原则

1. **可信 > 完备**：一条能解释清楚、样本外站得住的曲线，胜过十个漂亮的样本内结果。
   项目已经用 Walk-Forward 证明了这一点（MA 参数 IS 1.43 → OOS 0.13）。
2. **一笔账 > 两笔账**：任何"重算一遍"的逻辑都是 bug 温床（已修的双账本差 0.96%）。
   新增模块必须复用同一账本。
3. **数据可靠 > 策略精巧**：数据静默缺失可以让任何回测结论失效
   （已修的"失败即标记完成"会永久丢股票）。
4. **同一套代码跑回测与实盘**：回测和实盘用不同代码 = 回测结论不可信。

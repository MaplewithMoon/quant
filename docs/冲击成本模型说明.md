# 流动性冲击成本模型说明

> 新增 `execution/impact.py`，把原本写在 `scripts/semiconductor_rotation.py`
> 里的平方根冲击模型**上收进执行层**，成为统一、可切换、可测试的实现。

---

## 一、为什么需要

固定比例滑点假设「**下多大的单子成本都一样**」。真实市场并非如此：
下单量占当日成交量的比例越高，冲击成本越大，经验上是平方根关系。

后果：用固定滑点回测，**资金规模越大越失真**——100 万和 10 亿跑出同样的收益率，
而现实中后者根本吃不到那些价格。

原本项目里已经有一套平方根模型，但它写在框架外的轮动脚本里，
框架的 `SimulatedBroker` 只有固定滑点 → 同一份数据在两处跑出不同结果。

---

## 二、模型

```python
from execution.impact import FixedSlippage, SqrtImpact, NoSlippage, build_model

FixedSlippage(0.001)        # 成交价 = 市价 × (1 ± 0.001)      与下单量无关（默认）
SqrtImpact(k=0.02)          # 成交价 = 市价 × (1 ± k·√(Q/V))   随参与率平方根上升
NoSlippage()                # 零滑点，仅用于隔离变量做对照
```

- `Q` = 下单股数，`V` = 当日成交量（股），`Q/V` 即**参与率**
- 买入加价、卖出折价，对称
- 冲击上限 `max_impact`（默认 5%）兜住极端情况
- 成交量缺失时冲击为 0（**不静默编造价格**）

另外新增**参与率上限**：`max_participation`（默认 10%），
单笔最多吃掉当日成交量的这个比例，超出部分削量。防止回测里一笔巨单"无摩擦"全成。

---

## 三、k 必须校准（最重要的一节）

本模型是**参与率形式**，`k` 是无量纲系数，**不能照抄**。实测
（`000001` / MA / 2024 / 100 万本金 / 参与率中位数 0.099%）：

| k | 总收益率 | 平均冲击 | 相对无滑点 |
|---:|---:|---:|---:|
| 0（无滑点） | +3.95% | 0 | — |
| 固定滑点 0.1% | +1.89% | 0.10% | -2.06pp |
| **0.02** | **+2.72%** | **0.06%** | **-1.24pp** |
| 0.1（项目原实现） | -2.52% | 0.31% | -6.48pp |
| 0.5 | -23.49% | 1.45% | -27.45pp |

**k 从 0.1 变到 0.5，收益差 21pp** —— 这个参数足以决定策略生死。

理论/业界更常用的形式带上了波动率：

```
impact ≈ c · σ_daily · √(Q/V)        （σ 为该股日波动率，c 约 0.5~1）
```

上例参与率 0.1%、σ=2%、c=1 时冲击约 **6.3bp**，对应 **k ≈ 0.02**。
也就是说项目原来写死的 `k=0.1`，对一只低波动大盘股偏激进约 **5 倍**。

> 校准辅助：`.deps/calibrate_impact.py` 打印 k 从 0 到 0.5 的收益-冲击曲线，
> 并给出波动率形式对应的量级供对照。

**因此默认不启用**（`--impact-model fixed`），必须显式指定才生效——
避免一个未经校准的参数悄悄改变所有人的回测结论。

## 四、怎么用

```powershell
# 默认：固定滑点（与历史行为一致）
python scripts/backtest.py --symbol 000001 --strategy MA

# 启用平方根冲击（k=0.02，按波动率形式校准的推荐起点）
python scripts/backtest.py --symbol 000001 --strategy MA --impact-model sqrt --impact-k 0.02

# 参与率上限放宽到 20%
python scripts/backtest.py --symbol 000001 --strategy MA --impact-model sqrt --max-participation 0.2

# 零滑点（隔离变量做对照）
python scripts/backtest.py --symbol 000001 --strategy MA --impact-model none
```

编程式：

```python
from execution.impact import SqrtImpact
from backtest.engine import BacktestEngine

engine = BacktestEngine(initial_capital=1_000_000,
                        slippage_model=SqrtImpact(k=0.02),
                        max_participation=0.10)
```

## 五、成交明细实例（看成交价如何随冲击变化）

```
【固定滑点 0.1%】                     参与率 0.09%   冲击 0.1000%
  2024-01-31  buy  价 7.9500  125,700 股

【平方根冲击 k=0.1】                  参与率 0.09%   冲击 0.3040%
  2024-01-31  buy  价 7.9700  125,400 股

【平方根冲击 k=0.5】                  参与率 0.09%   冲击 1.5113%
  2024-01-31  buy  价 8.0600  124,000 股
```

同样的下单量：固定滑点恒为 0.1%，平方根模型按参与率给出不同的冲击，
且成交价越高、能买的股数越少（费用把现金吃掉了一部分）。

## 七、尚未实现

1. **波动率自适应**：当前 `k` 是常数。更严谨的做法是 `k = c·σ_t`，
   用 `data/preprocessor.py` 的 ATR 或滚动波动率逐日给定，需要把
   波动率透传到券商层。
2. **时间维度冲击**：真实冲击还取决于执行速度（拆单几天），
   当前是"单 bar 一次性成交"。
3. **冲击的永久/临时分解**：Almgren-Chriss 把冲击分为临时冲击与永久冲击，
   当前只建模了临时冲击（成交价变差），未建模对后续价格的影响。
